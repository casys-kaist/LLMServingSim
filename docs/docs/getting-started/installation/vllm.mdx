# vLLM setup

This step is **optional**. You only need the vLLM environment if you
plan to:

- **Profile** a new GPU or model (`python -m profiler`)
- **Benchmark** real vLLM end-to-end (`python -m bench run`)
- **Generate** ShareGPT-style workload datasets
  (`python -m workloads.generators`)

If you only want to run pre-profiled simulations on the bundled
hardware (RTXPRO6000 or RTX 4090), skip this page. Comparing stored benchmarks
with `python -m bench validate` also runs in the CPU-only simulator environment.

## Choose an install method

<Tabs groupId="install-method">
  <TabItem value="docker" label="Docker (recommended)" default>

The Docker path uses the official `vllm/vllm-openai:v0.28.0` image,
which already contains vLLM, PyTorch, and all CUDA dependencies.

That tag is built against **CUDA 13.x**. On a CUDA 12.9 host, edit the
image line in `scripts/docker-vllm.sh` to `vllm/vllm-openai:v0.28.0-cu129`
instead. The pin matters beyond the driver: every module under
`profiler/core/hooks/` binds to a vLLM *internal* API — the MoE router,
the model runner's KV cache groups, `layerwise_profile` — and those move
between releases, so a different vLLM can break profiling silently.

On a shared machine, set `VLLM_GPUS` to keep the container off GPUs
someone else is using. The inner quotes are part of the value:

```bash
VLLM_GPUS='"device=2,3"' ./scripts/docker-vllm.sh
```

Without them Docker splits on the comma and reads the second field as a
GPU *count*, failing with `cannot set both Count and DeviceIDs`.

### 1. (Optional) Set HF_TOKEN

Some model configs (Llama 3.x, gated Qwen variants) need a Hugging
Face token to auto-fetch:

```bash
export HF_TOKEN="hf_xxxxxxxxxxxxxxxxxxxxxxxxxx"
```

Skip this if you only profile open models or use locally-stored
configs.

### 2. Launch the vLLM container

From the repo root:

```bash
./scripts/docker-vllm.sh
```

This:

- Requests the GPUs selected by `VLLM_GPUS` (all GPUs if unset)
- Forwards `HF_TOKEN` from your shell
- Mounts the repo root to `/workspace` (so `python -m profiler`,
  `python -m bench`, `python -m workloads.generators` all work)
- Mounts the Hugging Face and vLLM compile caches to share them with the host
- Sets `--shm-size=16g` (vLLM needs this for inter-process tensors)
- Pre-installs `pandas`, `matplotlib` and `datasets` (the alpha fit,
  the bench plots, and the workload generators), and pins
  `nvidia-nccl-cu13` — installing `datasets` otherwise pulls a newer
  one than the image's torch declares, and pip reports the conflict
  but installs it anyway
- Applies the scripts in `scripts/patches/`, including the SM120 sparse-MLA
  fix and MiniMax-M3 MTP layer-name fix. The step-shape and MoE-activation
  logging patches install optional instrumentation, enabled only by their
  diagnostic environment settings. Inspect each patch's version guards when
  changing the pinned vLLM version
- Drops you into `bash` at `/workspace`

The container is named `vllm_docker`. Re-attach later with:

```bash
docker start -ai vllm_docker
```

### 3. Verify the install

Inside the container:

```bash
python -c "import vllm; print(vllm.__version__)"
nvidia-smi
```

You should see vLLM `0.28.0` and your GPU listed.

  </TabItem>
  <TabItem value="bare-metal" label="Bare metal (uv venv)">

For environments without Docker, install vLLM into a local `uv` venv.

### 1. Install `uv`

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

### 2. Run the installer

From the repo root:

```bash
./scripts/install-vllm.sh
```

This:

- Creates a local `uv` venv with Python 3.12
- Installs `vllm==0.28.0` (with `VLLM_USE_PRECOMPILED=1` for the
  prebuilt CUDA wheels)
- Adds `datasets`, `matplotlib` and `pandas` for workload generation,
  profile processing and bench plots

Activate the venv before running profiler / bench:

```bash
source .venv/bin/activate
```

Unlike the Docker launcher, the installer does not apply the repository's
vLLM source patches. Apply them in the activated environment when using the
same supported paths:

```bash
for patch in scripts/patches/*.py; do
  python "$patch"
done
```

### 3. Verify the install

```bash
python -c "import vllm; print(vllm.__version__)"
nvidia-smi
```

You should see vLLM `0.28.0` and your GPU.

**Bare-metal caveats**

**CUDA driver mismatch** is the most common failure mode. The
`vllm==0.28.0` wheel `VLLM_USE_PRECOMPILED=1` fetches is built against
CUDA 13.x — check your driver with `nvidia-smi` before assuming the
prebuilt wheel fits.

The script requests a pinned prebuilt package; setting or removing
`VLLM_USE_PRECOMPILED` does not make an incompatible wheel or driver compatible.
Use a compatible driver/package combination or the matching Docker variant.

Outside Docker you're responsible for `HF_TOKEN`,
`~/.cache/huggingface`, and shm size yourself.
